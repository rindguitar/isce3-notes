## なぜこの構造にしたか

すべての判断の根にあるのは **「`~/isce3` を汚さない」** という制約。
これが置き場所の設計をずっと規定していた。

| 決めたこと | 理由 |
|---|---|
| fork の wiki ではなく独立リポジトリ | **fork を消すと wiki も消える**。「いつでも見れる記録」と両立しない |
| fork のコードツリーにメモを置かない | upstream との差分に混ざり、PR の邪魔になる |
| `CLAUDE.md` を `~/isce3-notes` に置く | 起点さえ合わせれば `~/isce3` に何も置かずに済む |
| ビルドディレクトリも `~/isce3` の外 | 同上。`.gitignore` を触る必要すらなくなる |

詳細と却下した代替案は `decisions.md`。

### `logs/` と `reference/` を分けた理由

性質が違うため。

| | 中身 | 扱い |
|---|---|---|
| `logs/` | そのとき何が起きたか | **追記のみ。後から修正しない** |
| `reference/` | いまどうなっているか | 事実が変われば**上書き** |
| `glossary/` | そもそもそれは何か | 用語に出会うたび追記 |

ログを後から「正しい知識」に直してしまうと、
**「何を誤解していて、どう気付いたか」という情報が失われる**。
それは記録として価値がある部分なので、あえて直さない。

実際、初期構築ログには「FMA が原因かもしれない」という外れた仮説が残っている。
検証結果は同じログの末尾に追記した。

## 判明したこと: Claude Code の設定の効き方

ここが今回の主な学び。詳細は `glossary/07-claude-code.md` に整理した。

### `CLAUDE.md` は起点から親方向へしか探索されない

```
~/isce3 を起点にすると:
  ~/isce3/CLAUDE.md → ~/CLAUDE.md → /home/... → ~/.claude/CLAUDE.md
```

**`~/isce3-notes` は兄弟ディレクトリなので、絶対に見つからない。**

裏を返せば、**`~/isce3-notes` を起点にすれば `~/isce3` に何も置かずに済む。**
これが今回の解になった。

### ターミナル版と VS Code 拡張版で起点の決まり方が違う

| | 起点 |
|---|---|
| ターミナル | `cd` した場所 → `claude --add-dir ~/isce3` |
| VS Code 拡張 | **開いているワークスペースフォルダ** → `.code-workspace` で指定 |

`--add-dir` は CLI のフラグなので拡張機能版では使えない。
マルチルートワークスペースで `~/isce3-notes` を**先頭**に置くことで解決した。

このやり取りをしていた時点のセッションが、まさに
「`~/isce3` を開いていたので `CLAUDE.md` が読み込まれていない」状態だった。
**書いたつもりのルールが効いていない**という状況は起こりうる。

### `/clear` はプロセスを終了しない

作業ディレクトリも追加ディレクトリも維持され、`CLAUDE.md` は再読み込みされる。
**打ち直す必要はない。**

ただし会話の記憶は消えるので、**実質的にはセッションの区切り**。
`STATUS.md` に書いていないことは失われる。

→ `CLAUDE.md` の「終了時プロトコル」に `/clear` の前も含めると明記した。

### `@` インポート

`CLAUDE.md` に `@STATUS.md` と書くと自動で読み込まれる。
「セッション開始時に必ず読む」を、モデルの記憶に頼らず確実にできる。

## テンプレートを isce3 用に直したときの判断

手持ちのテンプレート（別プロジェクト用）を流用したが、4 箇所は意図的に変えた。

| 変更 | 理由 |
|---|---|
| **ソース読み取りの許可制を最上位に**（テンプレートには無い項目） | このプロジェクト最大の制約だから |
| **コメントは日本語 → 英語**（upstream に出すコードのみ） | 国際的な OSS で、PR は本家に出す。日本語コメントのままでは出せない |
| **Git 規約を 2 つに分割** | `~/isce3`（`develop`、直接コミット禁止、英語）と `~/isce3-notes`（`main`、直接コミット可、日本語）でルールが正反対 |
| **時間のかかる操作の定義を差し替え** | 「Docker 再ビルド / GPU 学習」→「フルビルド 15〜40 分 / フルテスト 10 分」 |

### サブエージェント委譲の抜け道を塞いだ

テンプレートには「コードベース探索・grep は haiku サブエージェントに委譲」とあった。
そのままだと**未許可ディレクトリを勝手に grep させる抜け道**になる。

→ 「サブエージェントにも許可制は適用される。委譲時は許可済みの範囲を明示的に伝える」
と追記した。
