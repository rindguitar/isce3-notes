## 判明したこと

### 1. `Orbit` は参照エポックを勝手に付け替える（確認済み）

これが今日いちばんの収穫。

`DateTime("2026-08-27T00:00:00")` を基準に `-100 s 〜 +300 s` の状態ベクトルを
作って `Orbit` に渡したところ、`orbit.reference_epoch` が
**`2026-08-26T23:58:20`（= 先頭の状態ベクトルの時刻）に変わっていた。**
時間範囲も `-100..300` ではなく `0..400` になる。

気付いたきっかけは、`interpolate(125.0)` の結果が解析解と **750 km** ずれたこと。
衛星速度 7504 m/s × 100 s = 750 km で、ちょうどエポックのずれ 100 秒ぶんだった。

基準を揃えて比較し直すと、状態ベクトル上では誤差 0、中間点でも 9.3e-10 m。
**補間は正しく、時刻の解釈だけが間違っていた。**

```
渡したエポック        : 2026-08-27T00:00:00.000000000
orbit.reference_epoch : 2026-08-26T23:58:20.000000000
ずれ [s]              : 100.0
```

教訓: **ISCE3 の時刻は常に `orbit.reference_epoch` 基準の秒数。**
渡したエポックが生き残ると思い込むと、静かに大きくずれる。
例外もエラーも出ないので、気付きにくい種類のバグになる。

### 2. rdr2geo / geo2rdr の往復精度（確認済み）

方位時刻 200 s・斜距離 850 km・right look・DEM 0 m で解いた結果。

| 検算 | 結果 |
|---|---|
| 求めた点までの距離を測り直す | 指定値との差 **2.3e-10 m** |
| その点のドップラを計算し直す | **1.8e-12 Hz**（ゼロドップラ条件） |
| geo2rdr で戻した方位時刻 | 差 **-2.4e-09 s**（地上距離で 0.018 mm） |
| geo2rdr で戻した斜距離 | 差 **0.0 m** |

3 つの拘束（距離・ドップラ・地形）を連立して解いていることが、
検算の数値からそのまま確認できた。

`rdr2geo` の戻り値は **`(経度, 緯度, 高度)` の rad/rad/m**（docstring に明記）。
`geo2rdr` の入力と同じ形式なので、往復がそのまま書ける。

### 3. 想定と逆だった: 地上間隔は近距離ほど「広い」

方位時刻を固定して斜距離を 25 km 刻みで振った。

```
   斜距離[km]     緯度[deg]     経度[deg]     入射角[deg]      地上間隔[km]
       800    6.526982    2.393494      30.6130             -
       850    6.641103    3.201052      36.6409        43.322
       900    6.740449    3.912019      41.3929        38.674
       950    6.830659    4.564328      45.3258        35.738
      1000    6.914554    5.176967      48.6790        33.707
```

**書く前は「近距離ほど詰まり、遠距離ほど広がる」と思っていたが、逆だった。**
実測で気付いた。

正しくは Δ地上 ≈ Δ斜距離 / sin(入射角)。
入射角が小さい近距離ほど分母が小さく、地上間隔は**広く**なる。
検算すると 25 km / sin(32.2°) = 46.9 km で実測の 46.873 km と一致する。

つまり **近距離ほど地上分解能が粗い。**
斜距離が等間隔でも地上は等間隔にならないので、
レーダ座標のままでは地図にならない。ジオコーディングが必要な理由がこれ。

### 4. 収束しない条件では黙って誤答を返さない（確認済み）

衛星高度 700 km より短い斜距離 600 km を渡すと、
地表に到達しないので解が存在しない。

```
RuntimeError: rdr2geo failed to converge
```

**例外を投げる。** 適当な値を返して先に進むのではない。
反復解法を使う関数として、期待どおりの振る舞い。

## `GeoToRdr` 失敗との関係

未解決の `GeometryTest.GeoToRdr`（`-O2` で失敗）は C++ 側のテストなので、
今日 Python 経由で geo2rdr が通ったことは**反証にならない**。

分かったのは「正常系は通る」ことだけ。追うなら、
**失敗する特定の入力条件を絞り込む**方向になる。
