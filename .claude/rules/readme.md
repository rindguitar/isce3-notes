# README 規約（README 編集時のみロードされる）

## 必須の配置

`logs/` `reference/` `drafts/` には `README.md` を必ず置く。
中身を追加・変更したら、**同じコミットで README も更新する**（別コミットに分けない）。

> このリポジトリにはコードが無いので、テンプレートの `src/` `scripts/` `tests/` は
> 上記 3 ディレクトリに読み替える。

## 各 README に書くこと

| ディレクトリ | 書く内容 |
|---|---|
| `logs/README.md` | 作業ログの**一覧（新しい順）**。日付・リンク・その日の要点を 1 行 |
| `reference/README.md` | 資料の一覧と、それぞれの**最終更新日** |
| `drafts/README.md` | 下書きの一覧と**状態**（作成中 / 確認待ち / 提出済み） |
| ルートの `README.md` | リポジトリ全体の目的・構成・運用ルール・現在の状態 |

## 定型の構成

```markdown
# <ディレクトリ名>

このディレクトリが何を担うかの 1〜2 行。

## 一覧

（表。何が・いつ・どういう状態か が 1 行で分かる粒度）

## 運用ルール

（追記のみ / 上書き更新 など、このディレクトリ固有の扱い）
```

## 原則

- **索引を古いままにしない。** ファイルを足したら一覧に行を足す。
  ここが古くなると「過去にどう解決したか」を探せなくなり、README の価値が消える
- **推測で書かない。** 内容の要約は実際にそのファイルを読んでから書く
- 一覧の表は「ファイルと役割の対応が 1 行で分かる」粒度にとどめる。詳細は各ファイルへ
- 概念そのものの解説（「そもそも GCOV とは」等）は README に書かず **wiki へリンク**する
  （`.claude/rules/wiki.md` 参照）
- **図は必要なときだけ。** 構造・流れ・依存関係を説明するときは Mermaid で描く
  （`.claude/rules/mermaid.md` に従う）。一覧表で足りるものを無理に図にしない
- パスは `~/...` で書く。ユーザ名を含む絶対パスを書かない
