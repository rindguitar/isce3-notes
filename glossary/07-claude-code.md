# 07. Claude Code の仕組み

作業の道具そのものの話。**設定ファイルがどこから読まれるか**を理解していないと、
書いたルールが効いていないことに気付けない。

## `CLAUDE.md` はどこから読まれるか

**起動時の作業ディレクトリを起点に、親方向へ遡って探索される。**
加えて `~/.claude/CLAUDE.md`（全プロジェクト共通）も読まれる。

```
起点が ~/isce3 の場合:
  ~/isce3/CLAUDE.md    ← 探す
  ~/CLAUDE.md          ← 探す
  /home/CLAUDE.md      ← 探す
  /CLAUDE.md           ← 探す
  ~/.claude/CLAUDE.md  ← 常に読まれる
```

**重要: 兄弟ディレクトリは探索されない。**
`~/isce3` を起点にしたとき、`~/isce3-notes/CLAUDE.md` は親でも子でもないので
永久に見つからない。

この性質のおかげで、**`~/isce3` に何も置かずに CLAUDE.md を使える**。
`~/isce3-notes` を起点にすればよいだけ。

### 置き場所ごとの効き方

| 置き場所 | 効く範囲 |
|---|---|
| `~/.claude/CLAUDE.md` | **全プロジェクト**。自分の作業方針を書く場所 |
| `~/CLAUDE.md` | ホーム配下の全プロジェクト |
| `<起点>/CLAUDE.md` | そのプロジェクトのみ。**通常はここ** |
| サブディレクトリの `CLAUDE.md` | そのディレクトリのファイルに触れたとき読まれる |

### `@` インポート

`CLAUDE.md` は `@パス` で他のファイルを取り込める。

```markdown
@STATUS.md
```

これを書いておくと、毎回 `STATUS.md` が自動で読み込まれる。
「セッション開始時に必ず読む」ものはこれで確実にできる。

ただし**取り込んだぶんだけ毎回のコンテキストを消費する**ので、
変化が速いもの（STATUS）と毎回必要なものだけに絞る。
用語集まで全部インポートすると重くなる。

## 作業ディレクトリの決まり方

**ここがターミナル版と VS Code 拡張版で違う。**

| | 作業ディレクトリ | 追加の指定 |
|---|---|---|
| ターミナル | `cd` した場所 | `claude --add-dir <パス>`（起動時フラグ） |
| VS Code 拡張 | **開いているワークスペースフォルダ** | `/add-dir <パス>`（会話内コマンド） |

`--add-dir` は CLI のフラグなので、拡張機能版では使えない。
代わりに**どのフォルダを開くか**で決まる。

### マルチルートワークスペース

VS Code は 1 つのワークスペースに複数フォルダを含められる。
`~/isce3-notes/isce3.code-workspace` がそれ:

```json
{
    "folders": [
        { "name": "isce3-notes", "path": "." },
        { "name": "isce3 (fork)", "path": "../isce3" }
    ]
}
```

**先頭のフォルダが主フォルダ**になるので、`CLAUDE.md` があるほうを先に書く。
パスは相対で書けるので、ユーザ名を含む絶対パスを残さずに済む。

> ⚠️ **未確認**: `/add-dir` で**追加した**ディレクトリの `CLAUDE.md` が
> 自動で読み込まれるかは確かめていない。
> 「`CLAUDE.md` があるフォルダを主フォルダにする」ほうが確実なので、
> 逆向き（`~/isce3` を開いて `/add-dir ~/isce3-notes`）は避けている。

## `/clear` の挙動

**会話履歴を消すだけ。CLI のプロセスは終了しない。**

| 維持されるもの | 消えるもの |
|---|---|
| 作業ディレクトリ | 会話の内容 |
| `--add-dir` で追加したディレクトリ | それまでの文脈・記憶 |
| 権限モードなどの設定 | |

`CLAUDE.md` は新しい文脈に**再読み込みされる**ので、
`@STATUS.md` のインポートも効く。起動し直す必要はない。

### ただし実質的にはセッションの区切り

**会話の記憶が消えるので、`STATUS.md` に書いていないことは失われる。**

だから `/clear` の前に `STATUS.md` を更新する。
これを守っていれば、`/clear` しても次の文脈が現在地を把握した状態で始まる。

逆に言えば、**`STATUS.md` の品質がそのまま引き継ぎの品質になる。**

## 主なファイルの役割

| ファイル | 役割 |
|---|---|
| `CLAUDE.md` | 作業のルール。**薄く保つ**。詳細は別ファイルへ逃がす |
| `STATUS.md` | 現在地・次の一手。**毎回更新する前提**の生き物 |
| `decisions.md` | 設計判断の記録（ADR）。**追記のみ** |
| `.claude/settings.json` | 権限やフックの設定 |

`STATUS.md` と `decisions.md` は Claude Code の規約ではなく、
**運用として決めたもの**。自動探索はされないので、`CLAUDE.md` から参照させる必要がある。

## サブエージェント

**別の文脈で動く補助的な Claude。** 探索やテスト実行のような
「出力が長いだけの作業」を任せると、メインの文脈を汚さずに済む。

安価なモデル（haiku）に回せばコストも下がる。

> ⚠️ このプロジェクトでは **サブエージェントにも読み取り許可制が適用される。**
> 未許可のパスを探索させない。委譲するときは許可済みの範囲を明示的に伝える。
> （委譲は許可を回避する抜け道ではない）

## 用語

| 用語 | 意味 |
|---|---|
| **コンテキスト** | Claude が一度に見られる情報の量。有限で、長い会話やファイルを読むと消費する |
| **スラッシュコマンド** | `/clear` `/add-dir` など、会話内で打つコマンド |
| **フック** | 特定の操作の前後に自動実行される設定。`.claude/settings.json` に書く |
